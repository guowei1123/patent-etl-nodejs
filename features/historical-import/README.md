# 历史专利导入

页面入口：左侧「历史数据导入」，地址 `/historical-import`。本模块集中管理 Excel 基础信息、说明书及权利要求 Parquet、PDF 附图的关联与发布。Next.js 页面、API 和导航保留少量框架入口，其余代码均位于本目录。

## 使用

1. 在项目根目录安装 Python 依赖：

   ```powershell
   python -m venv .venv-pdf
   uv pip install --python .venv-pdf/Scripts/python.exe -r features/historical-import/requirements.txt
   ```

   可通过 `PDF_PYTHON` 指定其他 Python 环境。数据库和 OSS/MinIO 使用项目 `.env` 配置。
2. 选择「基础信息」「说明书与权利要求」或「附图提取与导入」阶段，仅填写本阶段的服务器本机来源路径。基础信息只需要 Excel；正文可单独填写说明书或权利要求 Parquet；附图只需要 PDF 压缩包或目录。Excel 支持 `.xlsx`；PDF 支持单文件、目录、TAR/TAR.GZ/TGZ 和 ZIP，不展开嵌套压缩包。
3. 点击「检查来源字段」，展开「列名映射与处理范围」核对列名。说明书和权利要求分别设置公开号列、正文列；默认 Excel 列名对应提供的基础信息字段。
4. 点击「生成导入预览」，检查本阶段可导入记录及来源错误报告。附图候选可点击「查看附图」，查看原 PDF 页码、裁切区域、候选数量及去重后的资源数量。默认公告日期早于 2023-01-01，处理 100 件；数量 0 表示全部。已知日期按范围筛选；日期缺失的文献允许先保存，页面标记「基础信息待补齐」，日期补齐后才确定公告批次。
5. 点击「开始导入」。三类数据可以任意顺序导入：首次按完整公开号创建专利记录，后续复用同一 UUID 补齐当前阶段，其他阶段已有数据保留。正文可单独补入说明书或权利要求。配置或阶段修改后须重新预览。扫描 PDF 应开启 OCR。数据库存在重复公开号或申请号冲突时生成异常报告，不静默合并。

例如「附图 → 权利要求 → 基础信息 → 说明书」与「正文 → 基础信息 → 附图」均可。正文来源至少包含完整公开号列和本次正文列；PDF 以完整公开号命名；Excel 只强制要求公开号映射列，其他列缺失或为空时保持待补齐，已有值不被空值清除。填写了申请号或日期但格式无效时仍会报错。

预览不写业务数据库，不上传图片，但会在本地生成校验结果和 PNG。真实来源的列名、内容结构、体量应先用少量文献确认，之后再扩大范围。

## 版本和批次

- 使用规范化申请号归并同一专利，以完整公开号（保留 A/B/C/U/Y 及数字种类码）关联 Excel、Parquet 和 PDF。不使用 A 版正文补齐 B/C 版。
- 申请号归并兼容 FTP 的无校验位写法和 Excel 的含校验位写法，统一为申请号主体；Excel 原始字段仍完整保留。公开号的 A/B/C 种类码始终保留。
- 每个完整公开号独立关联，不因申请号缺失而把不同文献归成一件，也不因 B/C 出现而丢弃已暂存的 A 记录。基础信息按公开号补齐全部提供版本，候选数量有限时优先处理授权 B/C；已完整授权且开启清理时可跳过尚不存在的 A 记录。
- 授权版本的申请号、标题、公告日期、说明书、权利要求及附图全部齐备后，默认在同一事务中删除同申请 A 记录。未知申请号不执行归并或删除。A 的基础信息后到时，也会核对已经完整的 B/C，清理此前无法关联的 A 暂存记录。上传或入库失败不会删除 A 记录；原始来源文件保留。
- 按公开／公告日期生成批次，日期使用 `YYYYMMDD`：发明授权为 `CN-PA-TXTS-10-B-YYYYMMDD`，发明申请为 `CN-PA-TXTS-10-A-YYYYMMDD`，实用新型为 `CN-PA-TXTS-20-U-YYYYMMDD`。C 类文献归入 B 批次，历史实用新型 Y 类文献归入 U 批次，但原始公开号及种类码不变。批次与来源文件、导入任务 UUID 分开记录。
- 公告日期未知时，`cnipa.patent.batch_id` 与 `history_import_source.announcement_batch` 保持 NULL，不创建虚构日期批次。后续基础信息补齐日期时自动创建或复用正式批次，并更新历史记录的批次归属；已有 FTP 记录保留原批次。首次正式导入自动兼容旧表的批次非空约束。日期未知时不能据公开号推断年份，用户应确保来源属于要处理的历史范围。
- 历史批次与 FTP 批次名称相同，因此按数据库来源检查保护：无 FTP 路径的批次、包含历史导入来源的混合批次禁止执行 FTP 操作，也禁止通过普通批次删除接口删除；已有 FTP 批次的运行状态不被历史导入改写。旧 `HIST-` 批次仍保留保护，本次修改不自动迁移数据库已有数据。
- 附图阶段先把选中的 PDF 从压缩包解压到任务的 `unpacked/`，再提取图片。仅解压本次候选版本，保留包路径和成员名；拒绝路径穿越和 ZIP 符号链接，不修改原包。解压缓存保留用于复核，不自动删除。
- 图片对象为 `patents/history/{公告批次}/{公开号}/{PDF哈希}/{公开号}_drawing_001.png` 或 `_abstract_001.png`。日期未知时对象暂存在 `patents/history/PENDING/...`；补齐批次只更新数据库归属，保留已有对象键和图片资产，不重新上传或复制。优先提取独立图片区域，并保留原 PDF 页码及区域坐标；说明书附图分离不确定时保留页内主体区域。摘要图定位采用独立摘要附图页或首页下部图片区域，复杂扫描件须通过预览检查。
- 摘要图与说明书图复用 `lib/patent-image-matcher.ts` 的 SHA 与结构匹配算法。命中时对象存储只上传一张图、`image_asset` 只有一个资源，两条 `patent_image` 用途关联分别记录摘要和说明书图、匹配方法和旋转角度。相同 SHA 的已有资源可复用。没有可靠匹配时保留两图。任务本地提取候选仍保留供复核。
- 授权替换后的无引用图片进入清理队列。页面展示具体对象清单后可执行清理，服务端再次检查引用。每次最多 100 个对象，可重复操作。失败事务产生的其他孤立上传对象暂不自动扫描清理。
- 无附图文献只能在人工确认后填写「已确认无附图的公开号」。缺失、冲突或未识别的 PDF 不会自动当作无附图。

## 数据与代码

核心字段写入现有 `cnipa.patent` 和申请人、发明人、IPC 子表；Excel 其他字段完整保存为 JSON 到 `cnipa.history_import_source.metadata`，不会自动扩展现有搜索筛选字段。附图沿用 `cnipa.image_asset`、`cnipa.patent_image`，现有详情页可展示。

`cnipa.history_import_source` 保存任务、公告批次、完整公开号、来源文件、原始字段、内容指纹和 PDF 来源。`cnipa.history_import_part` 按专利记录保存基础信息、说明书、权利要求、附图及任务阶段的完成状态与指纹。`cnipa.history_image_cleanup` 保存待清理对象。

正文及附图来源公开号先去重到磁盘，再每 250 项查找已有记录，未命中则准备公开号记录，使用文献号索引匹配；单份来源可分批提交，不需要提供 Excel。每件文献独立事务，通过公开号事务锁避免不同阶段并发创建重复记录；申请号已知时先获取申请号锁，再获取公开号锁，协调授权清理。内容指纹按当前阶段计算，补齐基础信息不会使已完成正文或图片重复导入。多个后台任务可使用同一 PostgreSQL 和对象存储，当前不实现多个数据库分片之间的同步。

首次正式导入自动创建归并申请号的函数索引，避免对已有海量 FTP 数据逐件全表扫描。索引并发创建，不阻塞普通数据写入；首次初始化可能需要一些时间。预览不创建数据库表或索引。

| 文件 | 作用 |
| --- | --- |
| `page.tsx` / `api.ts` | 中文操作页面与接口 |
| `model.ts` / `jobs.ts` / `worker.ts` | 配置校验、磁盘任务状态和独立后台进程 |
| `prepare.py` | Excel 读取、版本选择、DuckDB 关联 Parquet、PDF 提取 |
| `database-snapshot.ts` / `images.ts` | 来源公开号分批匹配数据库、复用图片匹配及资源 |
| `publish.ts` / `cleanup.ts` | 事务发布、授权替换和对象清理 |
| `guards.ts` | 历史公告批次操作保护 |
| `pdf/` | PDF/OCR 工具及独立附图补录命令 |
| `__tests__/` | 版本替换、回滚、缺失资料和来源关联测试 |

任务文件位于 `data/historical-import/{任务UUID}/`，包括配置、状态、SQLite/DuckDB 工作数据、解压缓存、提取图片、候选清单和结果报告。此目录属于运行数据，需要预留空间；当前不会自动删除已完成任务。后台任务不要求浏览器持续打开。中断后可以创建新任务，内容指纹和固定图片键用于重复导入去重；没有实现来源扫描阶段的断点续跑。

## 验证

### F 盘历史图片存储

历史图片使用独立 MinIO 实例，保留原 FTP 图片实例。`.env` 中配置 `MINIO_HISTORY_ENDPOINT=http://localhost:9002`、`MINIO_HISTORY_DATA_DIR=F:\patent-data\minio-store`、`MINIO_HISTORY_EXECUTABLE=D:\minio\minio.exe`、`MINIO_HISTORY_CONSOLE_PORT=9003`，凭据复用已有 MinIO 配置。启动命令：

```powershell
node --env-file=.env --experimental-strip-types features/historical-import/start-history-minio.ts
```

历史对象键使用 `patents/{公告批次}/{公开号数字}/{图片名称}.png`，上传、读取、存在检查和清理均路由到历史实例；旧 `patents/history/` 键仍可读取。其他对象继续使用 `MINIO_ENDPOINT`。实际 MinIO 根目录是 `F:\patent-data\minio-store`，桶为 `patent-images`，图片落在 `F:\patent-data\minio-store\patent-images\patents\{公告批次}\{公开号数字}\{图片名称}.png`。不要直接将 PNG 写入 MinIO 内部目录。控制台地址为 `http://localhost:9003`；新实例需要在机器重启后重新启动，目前未注册自动启动服务。已有 Next.js 服务需重新启动以读取新的环境变量。

### PDF 图形提取范围

仅说明书附图（`drawing`）按图名分图：先读取原始图号，支持“图7”“图1(a)”“图1(b)”及带冒号说明的图名。文字层识别不足时，启用的 OCR 会补充图名并按位置去除重复识别。先在整页以图名为锚点归属图形连通区域，再将主体、标注和图名合并成完整裁剪范围；不再优先按最宽空白带切开，避免主体与图名之间的大空白被误作边界。支持左右排列和上方双列、下方通栏等混合布局。不同子图名视为独立图；相同图名重复出现时不强行分图。裁剪区域重叠、图名缺失或归属不确定时保留完整主体，排除页眉页脚。

本次图名分图不应用于摘要附图或正文图形。说明书正文继续提取内嵌插图、网格表格、独立数学公式及矢量图形；化学结构式保留为「正文插图」，不保证自动识别其化学语义。图片角色分别为 `drawing`、`abstract`、`body_figure`、`table`、`formula`，共用现有图片资产和去重机制，摘要的视觉匹配仅在真正附图中进行。

图名锚点归属时，代价为 `2 × 横向间隔 + 到图形底边的纵向距离 + 8 × 图形顶边低于图名的距离`（距离统一为 PDF 点）。优先选择位于图形连通区域底边下方的图名（容差 3 个 PDF 点）；没有下方候选时再使用额外惩罚。只作用于说明书附图。裁剪框重叠或归属不确定时保留整页正文区域，以 `drawing-page-body` 标识待检查的组合图。提取修订号为 9，重新生成预览后生效。

图片命名保留原文图名及字母大小写，例如 `说明书-图1A.png`、`说明书-图1(a).png`；摘要候选按 `摘要-图1.png` 编号。正文表格、公式、插图分别使用 `说明书-表1.png`、`说明书-公式1.png`、`说明书-正文图1.png`。同一专利内重名时追加页码和序号，避免覆盖。

首页只从“公布日”或“公告日”字段提取日期，不使用申请日。清单保存 `publication_date`、`announcement_batch`、`date_source`；PDF 无日期时可回退基础信息日期，否则归入 `PENDING` 待核对目录。日期与基础信息或数据库日期冲突时阻止发布。文件位于 `images/{公告批次或PENDING}/{公开号数字}/`。批次编码复用现有日期及种类码规则，导入时补齐 `patent.pub_date`、对应 `sync_batches` 与缺失的 `patent.batch_id`；保留既有 FTP 批次。

PDF 清单保存原始页码、裁剪坐标和提取方式；正文图形暂不自动嵌回 Parquet 段落。复杂扫描表格、混排公式或跨页内容仍需人工核对，不保证每个数学符号都能独立识别。提取修订号已更新，重新生成预览会使用新逻辑；旧预览不会自动更新。正文图形识别没有附图页时也可执行。

图片对象键简化为 `patents/{公告批次}/{公开号数字}/{文件名}`，例如 `patents/CN-PA-TXTS-10-A-20250207/119403808/说明书-图1A.png`。不包含 history、CN、种类码或哈希目录；批次编码本身保持现有格式。数据库和清单仍保留完整公开号、种类码、PDF 哈希和图片哈希。相同内容继续复用资产；同一路径已有不同内容时拒绝覆盖，需先清理原导入再导入。相同数字公开号在同一公告批次存在不同版本 PDF 时也会阻止本地目录覆盖。

```powershell
pnpm test -- features/historical-import/__tests__
.venv-pdf/Scripts/python.exe features/historical-import/__tests__/test_prepare.py
pnpm exec eslint features/historical-import app/historical-import app/api/historical-import components/layout/sidebar.tsx proxy.ts
```
