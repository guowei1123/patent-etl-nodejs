# 专利检索式语法规范

本规范描述专利工作台检索式检索的语法、字段、运算符与匹配规则。实现位于 `lib/patent-search-expression.ts`，经词法分析 → 语法分析 → AST → SQL 编译四步执行，最终生成参数化 SQL 在 PostgreSQL 上运行。

## 1. 语法概览

检索式由以下元素组成：

| 元素 | 说明 | 示例 |
|------|------|------|
| 关键词 | 不带空格的连续字符 | `电池` |
| 短语 | 用引号包裹的任意文本 | `"锂离子电池"` |
| 运算符 | 布尔连接词 | `AND`、`OR`、`NOT` |
| 字段 | 字段名加冒号或等号 | `TI:`、`IPC=` |
| 分组 | 圆括号 | `(A OR B)` |
| 字段分组 | 字段后紧跟圆括号 | `IPC:(H01M OR H01B)` |

## 2. 运算符

### 2.1 支持的运算符与别名

| 运算符 | 别名（英文） | 别名（符号） | 别名（中文） |
|--------|--------------|--------------|--------------|
| AND | `AND` | `&&` | `与`、`且` |
| OR | `OR` | `\|\|` | `或` |
| NOT | `NOT` | `!` | `非` |

别名大小写不敏感：`and`、`And`、`AND` 等价。

### 2.2 优先级

从高到低：

1. `NOT`（一元，右结合）
2. `AND`（二元，左结合）
3. `OR`（二元，左结合）

等价于：`NOT > AND > OR`。

### 2.3 隐式 AND

相邻的两个词或短语若未用运算符连接，自动按 `AND` 处理。

```
电池 新能源
-- 等价于
电池 AND 新能源
```

### 2.4 隐式 AND 的边界

隐式 AND 不会跨越显式的 `OR`。例如 `A B OR C` 解析为 `(A AND B) OR C`。

## 3. 字段检索

### 3.1 基本语法

```
字段名:值
字段名=值
字段名:"含空格的值"
字段名:(值1 OR 值2)
```

字段分隔符支持半角冒号 `:` 与等号 `=`，二者等价。

### 3.2 支持的字段与别名

| 字段 | 含义 | 别名 |
|------|------|------|
| `title` | 专利名称 | `TI`、`TITLE`、`名称`、`标题` |
| `abstract` | 摘要 | `AB`、`ABSTRACT`、`摘要` |
| `title_abstract` | 标题与摘要 | `TIAB` |
| `claims` | 权利要求 | `CL`、`CLAIM`、`CLAIMS`、`权利要求` |
| `description` | 说明书 | `DESC`、`DESCRIPTION`、`说明书` |
| `doc_number` | 公开/公告号 | `DOC`、`DOC_NUMBER`、`PN`、`PUBLICATION`、`公开号`、`公布号` |
| `app_number` | 申请号 | `AN`、`APP`、`APPNO`、`APP_NUMBER`、`申请号` |
| `pub_date` | 公开日 | `PD`、`PUBDATE`、`PUB_DATE`、`PUBLICATION_DATE`、`公开日`、`公开日期` |
| `kind` | 专利类型 | `TYPE`、`类型` |
| `applicant` | 申请人 | `PA`、`APPLICANT`、`申请人` |
| `inventor` | 发明人 | `IN`、`INVENTOR`、`发明人` |
| `assignee` | 专利权人/受让人 | `ASSIGNEE`、`权利人`、`受让人` |
| `agent` | 代理机构/代理人 | `AG`、`AGENCY`、`AGENT`、`代理` |
| `ipc` | IPC/CPC 分类号 | `IPC`、`CPC`、`分类号` |

字段别名大小写不敏感：`ti:`、`TI:`、`Ti:` 等价。

### 3.3 字段分组

字段后紧跟圆括号，可在该字段作用域内使用 `OR`/`AND`/`NOT`，避免重复书写字段名。

```
IPC:(H01M OR H01B)
申请人:(比亚迪 OR 宁德时代)
TI:(电池 AND 新能源) NOT TI:储能
```

字段分组内同样支持隐式 AND：

```
IPC:(H01M H01B)
-- 等价于 IPC:(H01M AND H01B)
```

## 4. 短语检索

使用双引号 `"` 或单引号 `'` 包裹的文本作为短语整体匹配，支持空格与特殊字符。

```
TI:"锂离子电池"
申请人:"国家电网公司"
```

短语内的引号可用反斜杠转义：

```
"包含\"引号\"的内容"
```

未闭合的引号会触发错误：`检索式中的引号未闭合`。

## 5. 通配符

文本字段匹配使用 `ILIKE`，支持以下通配符：

| 通配符 | 含义 | 示例 |
|--------|------|------|
| `*` | 匹配任意数量字符 | `电池*` → 匹配"电池""蓄电池组"等 |
| `?` 或 `？` | 匹配单个字符 | `200?` → 匹配"2000"~"2009" |

通配符适用于：`title`、`abstract`、`title_abstract`、`claims`、`description`、`doc_number`、`app_number`、`kind`、`applicant`、`inventor`、`assignee`、`agent`，以及默认字段检索。

若需匹配字面意义的 `%`、`_`、`\`，会被自动转义，无需手动处理。

## 6. IPC 分类号检索

### 6.1 标准化处理

IPC 字段检索会对输入值做标准化后再匹配，规则与 `normalizeClassificationCodeNorm` 一致：

- 去除所有空格
- 去除版本后缀（如 `(2006.01)`）
- 转大写

因此以下写法等价：

```
IPC:H01B 1/00
IPC:H01B1/00
IPC:h01b 1/00 (2006.01)
```

均标准化为 `H01B1/00` 后匹配。

### 6.2 前缀匹配

IPC 检索使用**前缀匹配**（`code_norm ILIKE '输入%'`），便于按层级检索：

| 输入 | 匹配范围 |
|------|----------|
| `IPC:H` | H 部全部 |
| `IPC:H01` | H01 大类全部 |
| `IPC:H01M` | H01M 小类全部 |
| `IPC:H01M10` | H01M10 大组全部 |
| `IPC:H01M10/0525` | 精确匹配该小组（及其下属未细分项） |

### 6.3 空格格式的 IPC 码

为兼容人工书写习惯，形如 `H01B 1/00` 的 IPC 码在检索时会被识别为单个分类号而非两个词：

- 字段检索：`IPC:H01B 1/00` → 标准化为 `H01B1/00`
- 默认字段检索：连续的 `H01B` 与 `1/00` 不会被当作两个独立词

> **边界提示**：默认字段检索会按空白拆分关键词。若 IPC 码本身含空格（如 `H01B 1/00`），默认检索会先拆词再各自标准化，可能匹配不精确。含空格的 IPC 码请使用 `IPC:` 字段检索。

### 6.4 CPC 分类号

`CPC` 为 `IPC` 字段的别名，二者等价。检索时会与 IPC 共用 `cnipa.patent_ipc` 表的 `code_norm` 列匹配。

## 7. 公开日检索

`pub_date` 字段支持三种粒度，自动转换为范围查询：

| 格式 | 说明 | 示例 |
|------|------|------|
| `YYYY` | 匹配整年 | `PD:2023` → 2023-01-01 至 2023-12-31 |
| `YYYY-MM` | 匹配整月 | `PD:2023-06` → 2023-06-01 至 2023-06-30 |
| `YYYY-MM-DD` | 匹配单日 | `PD:2023-06-15` |

日期校验：年份 ≥ 1，月份 1~12，日 1~31 且需为有效日期（如 2 月 30 日会报错）。

非法格式报错：`公开日字段仅支持 YYYY、YYYY-MM 或 YYYY-MM-DD` 或 `公开日字段日期格式不合法`。

## 8. 默认字段检索

不指定字段的词或短语，会在以下范围内匹配：

| 范围 | 字段 |
|------|------|
| 主表文本 | `title`、`doc_number`、`abstract`、`claims`、`description` |
| 关联表 | `patent_applicant.name`、`patent_inventor.name` |
| 分类号 | `patent_ipc.code_norm`（标准化后前缀匹配） |

示例：

```
比亚迪
-- 等价于在标题、公开号、摘要、权利要求、说明书、申请人、发明人、IPC 中任一字段匹配"比亚迪"
```

默认检索中的 IPC 匹配同样会做标准化，`H01B1/00` 与 `H01B 1/00` 均可命中（含空格者见 §6.3 边界提示）。

## 9. 分组与嵌套

圆括号可用于任意层级的分组，改变默认优先级：

```
(A OR B) AND C
NOT (A AND B)
TI:(电池 OR 电容) AND PD:2023
IPC:(H01M NOT H01M10)
```

未闭合的括号会报错：`检索式中的括号未闭合` 或 `字段检索式中的括号未闭合`。

## 10. 错误处理

检索式编译失败会抛出 `PatentSearchExpressionError`，常见错误：

| 错误信息 | 触发条件 |
|----------|----------|
| `检索式中的引号未闭合` | 短语引号未成对 |
| `检索式中的括号未闭合` | 圆括号未成对 |
| `字段检索式中的括号未闭合` | 字段分组括号未成对 |
| `检索式不完整` | 表达式末尾缺少操作数 |
| `检索式位置不合法: X` | 运算符或括号出现在不合法位置 |
| `字段检索式缺少查询值` | `字段:` 后未跟值 |
| `检索式不能包含空查询值` | 值仅含空白 |
| `不支持的检索字段: X` | 字段名不在别名表中 |
| `不支持的检索式字符: X` | 出现无法识别的字符 |
| `无法解析的检索式片段: X` | 表达式末尾有未消费的 token |
| `公开日字段仅支持 YYYY、YYYY-MM 或 YYYY-MM-DD` | 日期格式不符 |
| `公开日字段日期格式不合法` | 日期值越界（如 2 月 30 日） |

前端应在捕获上述错误时，将错误信息回显给用户，并保留检索式原文便于修正。

## 11. 完整示例

### 11.1 基础组合

```
电池 AND 新能源
"锂离子电池" OR 超级电容
NOT 储能
```

### 11.2 字段检索

```
TI:电池
申请人:比亚迪
IPC:H01M10
PD:2023
公开日:2023-06
```

### 11.3 字段分组

```
IPC:(H01M OR H01B)
申请人:(比亚迪 OR 宁德时代) AND 发明人:江浩然
TI:(电池 AND 新能源) NOT TI:储能
```

### 11.4 综合检索

```
TI:电池 AND (申请人:比亚迪 OR 申请人:宁德时代) AND PD:2023 AND IPC:H01M10
```

含义：标题含"电池"，申请人为比亚迪或宁德时代，公开日为 2023 年，IPC 为 H01M10 大组的专利。

### 11.5 否定与嵌套

```
(电池 OR 电容) NOT (储能 OR 备用)
TI:(新能源汽车 AND 电池) NOT CL:储能
```

### 11.6 多字段组合

```
TI:"动力电池" AND IPC:(H01M10/0525 OR H01M10/0587) AND 申请人:比亚迪 AND PD:2022-01 TO PD:2023-12
```

> 注：当前实现不支持 `TO` 范围运算符，日期范围需用两次 `PD:` 配合 `AND` 表达。例如 `PD:2022 AND PD:2023` 可分别命中两年，但无法表达"2022 年 3 月至 2023 年 6 月"的连续区间。如需范围检索，建议拆分为多个 `PD:` 条件或使用更宽的粒度。

## 12. 实现说明

### 12.1 执行流程

1. **词法分析**（`tokenize`）：将检索式拆分为 token（word / phrase / operator / field / lparen / rparen）
2. **语法分析**（`Parser`）：按优先级递归下降解析，构建 AST
3. **SQL 编译**（`compileNode` / `termToSqlBuilder`）：遍历 AST 生成参数化 SQL 片段
4. **参数绑定**：所有用户输入以 `$N` 参数形式传入，避免 SQL 注入

### 12.2 匹配模式

- 文本字段：`ILIKE '%值%'`（子串匹配，大小写不敏感）
- IPC 字段：`ILIKE '标准化值%'`（前缀匹配）
- 关联表字段（申请人、发明人等）：通过 `EXISTS` 子查询匹配

### 12.3 与其他筛选条件的关系

检索式生成的 SQL 片段会与其他筛选条件（IPC 分类树筛选、申请人范围、日期范围等）以 `AND` 组合，共同构成最终查询。检索式为空时返回 `null`，不影响其他筛选。

### 12.4 性能建议

- IPC 检索走 `code_norm` 索引，性能稳定，建议优先使用字段检索而非默认检索匹配 IPC
- 默认字段检索会触发多个 `EXISTS` 子查询，大库下建议缩小范围后再用
- `claims::text` 与 `description::text` 会将 JSONB 转文本后 LIKE，大文本字段开销较高，建议配合其他高选择性条件使用
- 通配符 `*` 在词首（如 `*电池`）会导致前缀匹配失效，需全表扫描，谨慎使用
